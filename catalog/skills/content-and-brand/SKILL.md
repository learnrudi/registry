# Content and Brand

Resolve the organization and this domain's authoritative source from the user's
request, selected workspace instructions, and existing source map (including
`ORGANIZATION.md` when present). If that identity or root is unclear, ask for it;
do not assume a personal path, provider, account, or database. Read applicable
instructions and domain entry records, then search only the requested material.
This skill works independently; the optional `$business` skill can help map sources.

Read the selected brand's current guidelines, resource map, and production
workflow before creating or editing material. Resolve which organization,
personal brand, channel, audience, and source item the request concerns; do not
supply the package publisher's brand or voice as a default.

For an existing item, continue its requested stage. For new raw input, check
whether the exact source is already filed before creating another item or
transcription. Use available specialized writing/media tools only as needed.
Preserve original-source references and distinguish draft, reviewed, approved,
scheduled, and published states. A finished asset is not proof of publication.

Keep originals and production masters in the approved asset store. Public site
changes belong in their actual code repository. Transfer only approved public
material there; brand-work access does not authorize posting, uploading, or
sending. Private client content retains its owning client boundary.

A bare invocation explains the domain and any configured source without fetching
sensitive records. A brief cites evidence dates, source links, status, and coverage;
local files alone do not establish current provider state. Missing or denied access
is a gap, never an empty result or permission to switch accounts. For requested
local edits, preserve existing work and follow source ownership/review rules.
External actions retain their explicit authorization and read-back requirements.

Examples: `$content-and-brand brief`, `$content-and-brand review the active content queue and its recorded stages`.
