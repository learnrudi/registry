## Phase 1: scope and interfaces

- Add `github/src/reviewer-source.ts`: fixed-origin authenticated Git object
  importer, complete bounded tree diff, verified blob/tree hashes, exact current
  repository/PR/base/head readback. Documentation-only pilot; reject executables,
  symlinks, submodules, unknown/truncated/oversized input and unauthorized paths.
- Add `github/src/reviewer-service.ts`: protected acceptance preparation and
  separate signer/publisher composition; preserve the unsigned controller.
- Add deployment sources under `github/deploy/`: reproducible manifest/package,
  protected runtime/config installation, root-supervised cross-UID one-shot
  invocation, independent proof and access/confinement probes, secure provisioning
  entrypoints. No daemon, sudoers exception, login item or scheduled trigger.
- Add supervised native connection in agent-hosts, reusing its RPC and observer.
- Add focused tests and operator docs; regenerate index through normal commands.
  No account IDs, host paths, private source, keys or run receipts in catalog.

Source and approved contract are data. Only installed trusted proof code executes;
repository code never executes in a signer/publisher process. Root supervision
owns identity changes and termination. The worker has no publisher access and no
process creation or service-invocation capability. Probes must prove the actual
installed boundary; configured UID names or synthetic fixtures are insufficient.

Policy selects one exact repository/PR/base/head and approved source paths, finite
lifetime and explicit owner acceptance. Publication rechecks current enable,
policy and revision state. The signer loads only controller-prepared evidence,
never model-authored authority. Uncertain operations remain for reconciliation.

Horizontal disposition: reuse authority validation, RPC observation, token grants,
signed verifier, publisher and journal. Add only missing owning boundaries. No
parallel merge coordinator or general runner. Commit slices: accepted libraries;
protected importer/composition; host/install package/docs, each with verification.

## Implementation proof record

Focused red/green evidence covers source import, signer, immutable accepted store,
supervisor protocol, host custody, ambiguous JSON, kernel confinement, process
drain races and disabled native capabilities. The root installer/orchestration
was implemented as a composition before all deterministic tests: strict TDD was
not followed for that block. Its privileged account/install/login/publication
behavior remains a mandatory live gap, not a claim supported by mocked fixtures.
The host's portable documentation records that limitation and recovery behavior.

An unauthenticated admin-peer 0.151.0 probe verified initialize, account read and
fresh thread configuration with Astra/xhigh, OpenAI, read-only/no network and no
instruction sources. No turn, credentials or inference was used. It identified
the runtime's `installation_id`/temporary-directory write requirements and the
denied bundled-skill installation log. Configuration remains protected.

Final gate commands and exact source hashes, acceptance verdicts, commit/PR and
peer receipts are retained in the private execution evidence. This record does
not itself assert that owner-only or live rollout gates have passed.


Independent snapshot-01 review rejected three gaps: human veto during publication,
catchable termination bypassing child drain, and emergency disable depending on
healthy runtime verification. Corrections share conservative review chronology
between publisher and merge readiness, latch stop signals across process creation
before bounded drain, and separate revocation custody from readiness. New reds
reproduced each defect, including a signal during child creation; focused greens

A fresh exact-snapshot acceptance review is required after these corrections.
